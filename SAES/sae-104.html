SAÉ 1.04
Se présenter sur Internet

Projet de validation de ressource : conception et développement d'un site web multipages en HTML/CSS. Le thème étant libre, j'ai choisi de présenter mon univers musical (MAO) dans une vitrine web complète.

📅 Semestre 1 — 2025
👥 Travail : individuel
🛠️ Technologies : HTML, CSS, Flexbox/Grid, GitHub Pages
🌐 Publication : GitHub Pages
🐙 Repository : Tezix-cyber/site
📋

Description & Objectifs

Contexte du projet et compétences visées

La SAÉ 1.4 — Se présenter sur Internet est un projet individuel de validation de ressources dont l'objectif est la conception et le développement intégral d'un site web vitrine multipages (3 pages minimum), codé à la main en HTML5 et CSS3.

Le thème étant libre, j'ai choisi de présenter ma passion pour la Musique Assistée par Ordinateur (MAO), en créant un site qui expose les principes de la synthèse sonore, de la production musicale en home-studio, et mes projets personnels de création.

L'enjeu technique consistait à respecter un cahier des charges strict : utilisation exclusive de techniques de positionnement modernes (Flexbox et CSS Grid), conception adaptative (Responsive Web Design), intégration d'animations CSS fluides, respect des standards du Web de validation W3C et de la norme d'accessibilité numérique WCAG 2.0 niveau AA. Le code source devait être suivi sur Git, hébergé sur GitHub, et publié sur GitHub Pages.

Tâches réalisées

Ta contribution personnelle et les étapes du travail

Afin de mener à bien le développement de ce site vitrine dans le temps imparti (rendu fixé au 19 décembre 2025), j'ai suivi une méthodologie rigoureuse de gestion de projet et d'intégration web :

1. Cadrage et Planification (Ressource R1.15) :

Définition de l'arborescence des tâches via une MindMap et un WBS. Établissement d'un rétroplanning détaillé (diagramme de Gantt) pour planifier les phases de conception, maquettage, codage, tests et déploiement. Initialisation d'un tableau Kanban (Trello) pour le suivi quotidien.

2. Conception visuelle & Charte graphique :

Création de wireframes et maquettes papier de l'interface. Choix d'une charte graphique immersive (fonds sombres, nuances de violets profonds et d'éclats néon inspirés des stations de travail audionumériques) avec des polices lisibles et des contrastes élevés.

3. Développement Front-End HTML5 / CSS3 :

Codage sémantique des trois pages : page d'accueil (visuelle et synthétique), page thématique MAO (riche en explications techniques sur la synthèse et les effets) et page à propos (présentation de l'auteur, Nathan Duval). Positionnement des éléments via Flexbox et CSS Grid, et intégration de keyframes CSS pour les transitions.

4. Audit d'accessibilité et validation de conformité :

Tests de contrastes de couleurs, validation de la présence de balises d'accessibilité (attributs ARIA, textes alternatifs d'images) et passage du code sous les validateurs officiels W3C pour corriger d'éventuelles erreurs de syntaxe.

5. Versioning et Déploiement :

Suivi de versioning rigoureux sur un dépôt GitHub public, avec des commits atomiques décrivant précisément les ajouts. Configuration du déploiement continu via GitHub Pages et rédaction d'un fichier README.md exhaustif.

Autoévaluation réflexive

Analyse critique de ton expérience et de ta progression

💡 Quelles difficultés as-tu rencontrées ?
La principale difficulté a été de respecter scrupuleusement les exigences de la norme d'accessibilité WCAG 2.0 AA (notamment les ratios de contraste pour le texte sur fond sombre) tout en maintenant le design sombre inspiré des séquenceurs audio (DAW). La gestion du positionnement adaptatif avec CSS Grid pour la galerie d'instruments et le respect des délais serrés de planification R1.15 ont également représenté de réels défis.
🔓 Comment les as-tu surmontées ?
J'ai utilisé des outils de diagnostic comme Lighthouse et l'extension WAVE pour ajuster dynamiquement les couleurs de contraste et corriger la sémantique HTML. Pour la gestion du temps, le diagramme de Gantt (rétroplanning) et notre suivi de tâches Kanban (Trello) ont permis de repérer les retards de maquettage et de redéployer mes efforts sur la phase d'intégration technique.
📚 Qu'as-tu appris de nouveau ?
Ce projet m'a permis de maîtriser l'architecture responsive mobile-first et d'appréhender pour la première fois les contraintes d'accessibilité numérique (normes WCAG). J'ai également consolidé l'utilisation d'outils de gestion de projet (WBS, Gantt, Kanban) et le workflow de publication professionnelle avec Git et GitHub Pages.
🔄 Comment pourrais-tu réutiliser ces acquis ?
Ces compétences de développement sémantique, d'audit d'accessibilité et de pilotage de projet sont directement réutilisables pour toutes mes réalisations web futures (notamment dans la création de nos prochains livrables de SAÉ et portfolios) ainsi que dans le monde professionnel.
