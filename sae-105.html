📂 SAÉ 1.5

SAÉ 1.5
Traitement de données

Projet Python orienté OpenStreetMap : récupération de données via API OSM/Overpass, production de statistiques et génération de fiches aux formats Markdown et HTML.

📅 Année : 2025-2026
👥 Travail : binôme (ou autonomie si effectif impair)
🛠️ Technologies : Python, JSON, API OSM/Overpass, Markdown
🐍 Langage : Python 3.11 (salle TP)
⏳ Rendu : déc. 2025 / janv. 2026 selon statut
📋

Description & Objectifs

Contexte du projet et compétences visées

La SAÉ 1.5 (Traitement de données) avait pour objectif d'automatiser l'acquisition, la modélisation, le traitement et la restitution d'informations géographiques issues d'OpenStreetMap (OSM). En s'appuyant sur le langage de programmation Python, ce projet visait à manipuler des formats de données semi-structurés (JSON, XML) issus d'API Web (Overpass, Nominatim, tuiles cartographiques d'OSM) et à les restructurer sous forme de documents formatés (Markdown et HTML).

Dans le cadre de mon sujet d'étude libre, j'ai choisi de répertorier et d'analyser l'intégralité des boîtes de nuit à l'échelle de la France, soit un ensemble de données représentant environ 1 150 établissements. L'objectif sous-jacent était de mettre en lumière la complétude (ou le manque) de métadonnées géographiques critiques sur OpenStreetMap pour un secteur d'activité spécifique.

Ce projet a servi d'évaluation pratique pour valider nos compétences en algorithmie, en manipulation de flux de données réseau via des protocoles HTTP, en écriture de fichiers locaux, et en génération dynamique de pages web statiques respectant une charte graphique définie.

📡 Acquisition & Requêtage Réseau

  • Requêtes API Overpass : Rédaction de requêtes Overpass QL complexes avec filtrage sur zone géopolitique (France) et critères de tags.
  • Géocodage inverse : Interrogation de l'API Nominatim pour convertir les coordonnées géographiques brutes (latitude/longitude) en adresses structurées.
  • Téléchargement de tuiles : Récupération dynamique d'images raster (.png) depuis le serveur de tuiles OSM.

🐍 Algorithmique & Traitement Python

  • Gestion de la complétude : Implémentation de tests de présence de clés pour éviter les plantages lors de la lecture de tags optionnels (wheelchair, opening_hours, fee).
  • Résilience réseau : Gestion des limites d'appels API (code HTTP 429 et 504) par des boucles d'attente exponentielle.
  • Statistiques descriptives : Calcul automatisé des taux de présence de données sur un large échantillon de nœuds (1 150 points d'intérêt).

Tâches réalisées

Déroulement technique et étapes de développement

1. Développement du convertisseur Markdown vers HTML (md_to_html.py)

Afin de restituer des rapports lisibles, j'ai développé un script autonome qui exploite le package Python markdown pour convertir du balisage brut en fichier HTML5. J'y ai intégré l'injection d'une feuille de style CSS embarquée (gestion de la typographie, ombres de boîte, boutons de navigation et surbrillance au survol) pour s'assurer que les rapports générés soient soignés, lisibles et modernes.

2. Conception du générateur de fiches locales (fiche_osm.py)

Ce script interroge l'API standard d'OpenStreetMap (endpoint /api/0.6/node/[id].json) pour extraire l'ensemble des tags associés à un nœud spécifique. Il convertit ensuite les coordonnées du nœud en identifiant de tuile cartographique (formules trigonométriques basées sur la projection de Mercator), télécharge la tuile OSM correspondante, dessine un marqueur rouge (pin) à l'emplacement précis avec la bibliothèque Pillow (PIL), puis génère une fiche d'information complète en Markdown avant de la compiler en HTML.

3. Acquisition globale des données par Overpass QL (code overpass)

Pour cibler l'ensemble des boîtes de nuit à l'échelle de la France métropolitaine, j'ai conçu une requête structurée en langage Overpass QL. La requête recherche récursivement les objets de type node, way et relation portant le tag [amenity=nightclub] dans la zone géographique délimitée par la frontière française (référencée par son code d'aire administrative globale).

4. Analyse statistique et interface interactive (infos_locales.py)

J'ai programmé le script d'analyse statistique globale qui demande à l'utilisateur de saisir via la console la zone d'étude de son choix (ex. Caen, Normandie, France). Il construit la requête Overpass à la volée, l'exécute auprès de l'API Overpass, et calcule en Python le taux de remplissage pour six tags cruciaux : horaires d'ouverture (opening_hours), site internet (website), tarification (fee), droit de fumer (smoking), présence de karaoké (karaoke) et accessibilité handicapé (wheelchair).

5. Intégration de la robustesse réseau & Gestion d'erreurs

J'ai mis en place un mécanisme de tentatives successives (jusqu'à 5 essais) pour gérer les codes de retour HTTP transitoires (429 Trop de requêtes, 504 Timeout) fréquemment rencontrés sur les serveurs publics d'Overpass. Le programme utilise sys.exit() avec un message explicite lorsque la requête ne renvoie aucun élément afin d'éviter les erreurs de division par zéro dans le calcul des moyennes.
