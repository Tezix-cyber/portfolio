SAÉ 1.5
Traitement de données

Projet Python orienté OpenStreetMap : récupération de données via API OSM/Overpass, production de statistiques et génération de fiches aux formats Markdown et HTML.

Description & Objectifs

Contexte de la SAÉ et compétences visées

La SAÉ 1.5 — Traitement de données est un projet axé sur la programmation structurée et l'exploitation de sources de données géographiques ouvertes. L'objectif principal était de concevoir un système en Python capable d'interroger la base de données cartographique OpenStreetMap (OSM), d'en extraire des données ciblées à l'aide de requêtes complexes, puis de formater et d'analyser ces informations pour produire des rapports synthétiques.

Le thème d'étude choisi pour ce projet porte sur les boîtes de nuit (nightclubs) en France, représentant un jeu de données national d'environ 1 150 établissements. L'enjeu était de cartographier ces établissements et d'analyser leur niveau de complétude sur OpenStreetMap (horaires, présence en ligne, tarifs, aménagement PMR, espaces fumeurs).

Ce projet a permis de comprendre le cycle de vie de la donnée : depuis sa récupération brute au format JSON via des API REST (API OSM et Overpass API), en passant par son nettoyage et son analyse statistique en Python, jusqu'à sa restitution visuelle sous forme de fiches documentaires et de rapports web générés automatiquement en Markdown et HTML/CSS.

📡 API REST & JSON

  • Extraction automatisée de nœuds spécifiques via l'API officielle d'OpenStreetMap.
  • Requêtage géographique national de masse à l'aide d'Overpass QL et de l'interpréteur de requêtes Overpass API.
  • Parsing et parcours d'arborescences complexes de dictionnaires et listes imbriquées en format JSON.

🐍 Algorithmique & Traitement

  • Conception modulaire en Python avec des fonctions documentées et typées (Docstrings).
  • Gestion de la robustesse : tests d'existence de tags pour éviter les crashs sur données incomplètes.
  • Algorithmes de calcul de statistiques descriptives (fréquences, pourcentages arrondis).

🗺️ Cartographie & Restitution

  • Calcul trigonométrique de coordonnées de tuiles OSM (longitude/latitude vers coordonnées X/Y à zoom 12).
  • Génération de fiches individuelles avec cartes d'implantation locale modifiées dynamiquement via PIL/Pillow.
  • Conversion automatisée de rapports textuels Markdown en pages web HTML stylisées via le module markdown.

Tâches réalisées

Ta contribution personnelle et les étapes du travail

Pour réaliser cette chaîne de traitement complète, j'ai développé plusieurs scripts Python complémentaires assurant l'acquisition, le traitement et la mise en forme des données cartographiques :

1. Convertisseur de rapports Markdown vers HTML (md_to_html.py) :

Développement d'un module utilisant la bibliothèque markdown pour lire des fichiers textuels structurés et les exporter sous forme de pages HTML complètes. J'y ai intégré un modèle de mise en page CSS moderne (avec effets de survol, ombres portées et polices système) pour optimiser la lisibilité des fiches générées.

2. Générateur de fiches de localisation individuelles (fiche_osm.py) :

Écriture d'un script téléchargeant les données JSON d'un nœud OSM spécifique à partir de son identifiant (ex: 7991140667). Le programme calcule mathématiquement la tuile de carte correspondante à son emplacement géographique à un zoom donné, télécharge cette tuile depuis les serveurs OSM, dessine un marqueur rouge (pin de localisation) et écrit le nom de la commune dessus à l'aide de la bibliothèque PIL (Pillow). Il génère enfin une fiche Markdown répertoriant tous les tags (attributs) du nœud, puis la compile en HTML.

3. Extraction nationale et analyses statistiques (infos_locales.py) :

Développement d'un script console interactif permettant à l'utilisateur de saisir une zone géographique (ex: France, Normandie, Caen). Le programme construit dynamiquement une requête Overpass QL, interroge l'API Overpass, sauvegarde le résultat brut dans dataset.json et calcule des statistiques de complétude sur les 1150 établissements trouvés. Les statistiques incluent la proportion de sites internet référencés, d'horaires d'ouverture documentés, d'accès PMR (PMR/handicapés), d'espaces fumeurs et de karaokés. Un rapport Markdown récapitulatif avec les pourcentages calculés et la liste détaillée de tous les établissements est automatiquement créé puis converti en HTML.

4. Fiabilisation du code et gestion des erreurs de communication :

Mise en place de structures robustes pour parer aux instabilités d'Internet ou de l'API : création de boucles de tentatives multiples (retry) avec temporisation progressive (time.sleep()) lors d'un code retour HTTP 429 (Too Many Requests) ou 504 (Gateway Timeout), et interception des erreurs de parsing JSON avec messages utilisateur explicites.
